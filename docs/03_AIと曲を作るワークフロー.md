# AI（Claude）と一緒に 0 から曲を作るワークフロー

このツールは「全部 AI 任せ」ではなく、**人間が方向を決め、AI が理論と作業を担当し、聴いて直す**ことを繰り返す設計です。
曲はすべてテキスト（YAML）なので、Claude が読んで・直して・理由を説明できます。

```
 ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
 │①コンセプト│ → │②作曲仕様  │ → │③compose  │ → │④render   │
 │ (人+AI)  │   │ spec.yaml│   │ 自動作曲  │   │ 聴く      │
 └──────────┘   └──────────┘   └──────────┘   └────┬─────┘
                       ↑                            │
                       └──── ⑤ AI と相談して直す ←───┘
```

## ① コンセプトを決める（会話で）

Claude にこう聞くと進めやすい:

> 「卒業がテーマの、切ないけど前向きな曲を作りたい。テンポは速め」

決めること:
- テーマ・物語（誰が、何を、どう感じている）
- 雰囲気 → キー（明るい: メジャー / 切ない: マイナー or 王道進行）、テンポ（バラード 70〜90 / ポップ 110〜130 / 疾走 140〜）
- 構成（`intro, verse, prechorus, chorus, ...`）

## ② 作曲仕様を書く（`specs/xxx.yaml`）

例は `specs/hajimari.yaml`。書くのは**歌詞・コード進行・構成**だけ。

```yaml
title: はじまりのうた
key: G major
tempo: 124
style: pop
seed: 3
structure: [intro, verse, prechorus, chorus, ...]
sections:
  verse:
    progression: カノン進行        # 進行名・ディグリー(I V vi IV)・コード名(G D Em C)どれでも
    lyrics: |
      まどをあけたら
      かぜがはこんだ
  chorus:
    progression: 王道進行
    energy: high                   # low / mid / high（伴奏の厚さ・音域）
    lyrics: |
      はじまりのうたを
      ...
  verse2:
    base: verse                    # 2番: メロディは verse と同じ、歌詞だけ違う
    lyrics: ...
```

歌詞のコツ:
- **1 行 = 1 フレーズ**。1 行 5〜12 モーラくらいが歌いやすい（2 小節に 8 分音符で最大 14 モーラ）
- 対になる行（1 行目と 3 行目など）の**モーラ数を揃える**と、同じ旋律が再利用されて覚えやすい曲になる
- サビは短い言葉の繰り返し + 一番言いたいこと

セクションのオプション:

| キー | 意味 | 既定 |
|---|---|---|
| `progression` | コード進行（1 小節 1 コードで繰り返す） | `I V vi IV` |
| `chords` | `progression` の代わりにコードを直接（`C | F G | Am`） | |
| `chords_per_bar` | 1 小節のコード数 | 1 |
| `lyrics` | 歌詞 | なし（インスト） |
| `bars` | 小節数（インスト部分や、余白を作りたい時） | 歌詞から自動 |
| `phrase_bars` | 1 フレーズの小節数 | 2 |
| `energy` | low / mid / high | 名前から推測 |
| `register` | 音域 low / mid / high | energy に従う |
| `transpose_range` | 音域を半音単位でずらす（男性向けなら -5 など） | 0 |
| `base` + `fit` | 他セクションのメロディを流用して歌詞だけ替える | |

## ③ 自動作曲

```bash
python -m musicai compose specs/hajimari.yaml       # → songs/hajimari.yaml
```

`seed` を変えると別のメロディ案になります。いくつか作って聴き比べるのがおすすめ。

## ④ 聴く

```bash
python -m musicai render songs/hajimari.yaml         # → output/hajimari.mp3 ほか
python -m musicai render songs/hajimari.yaml --mute vocal   # カラオケ版
```

出力:
| ファイル | 用途 |
|---|---|
| `.mp3` / `.wav` | 試聴（母音で歌う仮歌シンセ + 伴奏） |
| `.mid` | DAW（GarageBand, Cubase, Studio One, Domino 等）で編集。歌詞イベント付き |
| `.musicxml` | 楽譜（MuseScore）/ **歌声合成ソフト**（NEUTRINO, Synthesizer V, VOICEVOX 系など）に読み込んで本物の歌声に |
| `_歌詞.txt` | 歌詞カード（コード付き） |

## ⑤ AI と相談して直す

`songs/xxx.yaml` は人間にも AI にも読めるテキストです。Claude への頼み方の例:

- 「サビの最後をもっと高く盛り上げて終わりたい」
- 「Aメロのリズムが単調。少し跳ねさせて」
- 「Bメロからサビへの繋ぎで、Bメロ最後のコードをドミナント（V）にして」
- 「2 番の歌詞を書いて。1 番と同じモーラ数で、韻も揃えて」
- 「サビの『いまうたおう』のアクセントとメロディが合ってるか見て」
- 「全体を半音上げて」「テンポを 100 に」「バラードアレンジにして（style: ballad）」

Claude は `python -m musicai validate`（ファイル構造）→ `check`（楽曲ルール）の順で検証し、`render` で書き出してから返します。

### ファイルの形式（スキーマ）

曲ファイルと作曲仕様は、それぞれ `schemas/song.schema.json` / `schemas/spec.schema.json` に沿って書きます。
先頭に `schema_version: 1` が必須です。`validate` は「キーの綴り・型・選択肢」が合っているかを調べ、
音符数とモーラ数の一致などの音楽的なチェックは `check` が行います。
`schema_version` が無い古いファイルは `python -m musicai migrate songs specs` で直せます（コメントは消えません）。

## 本物の歌声にするには

このツールの仮歌シンセは「母音だけで歌う」簡易版です。歌詞をはっきり歌わせたい場合:

1. `output/xxx.musicxml` を歌声合成ソフトに読み込む
   - **NEUTRINO**（無料・MusicXML を直接読める）
   - **Synthesizer V**（MIDI/MusicXML インポート）
   - **VOICEVOX**（ソングモード）/ **UTAU**（MIDI インポート）
2. 書き出した歌声 WAV と、`--mute vocal` で作ったカラオケ版を DAW や Audacity で重ねる
