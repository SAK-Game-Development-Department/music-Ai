# プロンプトテンプレートの使い方と、スキーマ通過率の測り方

`prompts/` のテンプレートは、AI（Claude など）が曲ファイルを**スキーマ（`schemas/*.json`）に沿って安定して**
作る・直す・見るためのものです。

| ファイル | 用途 | AI の出力 |
|---|---|---|
| `prompts/compose.md` | テーマ・キー・テンポから作曲仕様（`specs/xxx.yaml`）を作る | 仕様の YAML ＋ 説明 |
| `prompts/revise.md` | `songs/xxx.yaml` を理論的な理由つきで直す | 修正後の曲 YAML ＋ 理由の説明 |
| `prompts/review.md` | 理論・モーラ数・スキーマの観点でレビューする | レビュー文のみ（YAML なし） |

使い方: テンプレートの `{{…}}` を埋めて、AI にそのまま渡します。Claude Code ならファイルを読ませるだけで使えます
（`CLAUDE.md` から辿れます）。AI は書き出す前に `validate` と `check` を実行する決まりです。

## スキーマ通過率の目標と測り方

**目標: テンプレートを使ったときの出力の 90% 以上が `validate` に合格すること。**
`revise.md` の出力は曲（`songs/` 形式）、`compose.md` の出力は仕様（`specs/` 形式）として測ります。
`review.md` は YAML を出さないので対象外です。

測定は AI を呼び出さず、集めた出力を後から数えます（`scripts/measure_prompts.py`）。

1. **出力を集める**: 同じテンプレートで、テーマや依頼を変えて 20 回以上（多いほど正確）AI に頼む。
   毎回**新しい会話**で、テンプレート以外の補足を足さない。
2. **1 回 1 ファイルで保存する**: AI の返答をそのまま `.md` で保存してよい（最初の ```yaml ブロックを取り出して測る）。
   YAML だけ取り出して `.yaml` で保存してもよい。種類ごとにフォルダを分ける
   （例: `outputs/compose/01.md …`、`outputs/revise/01.md …`）。
3. **測る**:
   ```bash
   python scripts/measure_prompts.py outputs/compose/ --kind spec
   python scripts/measure_prompts.py outputs/revise/  --kind song
   ```
   不合格のファイルは、エラー位置（キーのパス）と理由が出ます。最後に `スキーマ通過率: 19/20 = 95%（目標 90%）→ 達成` のように表示され、
   目標未達なら終了コード 1 になります（`--threshold` で目標を変更可）。
4. **改善する**: 不合格が多いエラーを見て、テンプレートの該当箇所（使えるキー・形式の説明）を直し、1 から測り直す。
   測定結果と日付は、テンプレートを直した PR の説明に書いておく。

注意:
- ここで測るのは**ファイルの構造**（キーの綴り・型・選択肢・`schema_version`）だけです。音符数とモーラ数の一致などは `check` の役割です。
- 通過率は AI のモデルや会話の仕方で変わります。測ったモデル名も記録してください。
- `{{…}}` を埋め忘れた・読み指定のない漢字を含む、などの問題は `compose`／`check` の段階で見つかります。
