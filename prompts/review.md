# レビュープロンプト：曲を理論・モーラ数・スキーマの観点で見る

あなたは音楽理論に詳しいレビュアーです。`songs/{{曲名}}.yaml` を読み、次の 3 つの観点で評価してください。
**ファイルは変更しません**（直すのは `revise.md` の役割です）。

## 入力

- 対象: `songs/{{曲名}}.yaml`
- 知りたいこと（任意）: {{観点  例: サビのアクセントとメロディが合っているか}}

## 事前に実行する（結果をレビューに含める）

1. `python -m musicai validate songs/{{曲名}}.yaml`（スキーマ: `schemas/song.schema.json`、`schema_version: 1`）
2. `python -m musicai check songs/{{曲名}}.yaml`（音符数・モーラ数・小節の長さ・警告）
3. `python -m musicai mora "<気になる歌詞>"`（モーラの数え方を確かめたいとき）

## melody 記法（`songs/*.yaml` を読むとき・直すときの規則）

`melody: "音名:拍数 ..."` — 音名は `C4`（真ん中のド）・`F#4`・`Bb3`、拍数は `1` `0.5` `1/2`。
拍数を省略すると直前と同じ長さ、休符は `r`（`r:1`）、`~` を付けた音は新しい文字を歌わないメリスマ（`G4:1~`）、`|` は小節線。

## 観点

1. **スキーマ**: `validate` が合格か。不合格なら、エラー位置（キーのパス）と直し方
2. **モーラ数**: セクションごとに「歌う音符の数 = 歌詞のモーラ数」か（休符と `~` の音は数えない）。`要調整` の箇所、`fit: true` に頼っている箇所、フレーズの切れ目と休符の位置。歌詞の `{漢字|よみ}` の読み
3. **理論**（docs/01_音楽の作り方.md）:
   - 強拍にコードの構成音が置かれているか、跳躍が多すぎないか
   - フレーズが山なりか、フレーズ末が長い音 + 休符か
   - サビが曲中で一番高く、盛り上がり（`energy`・`style`）と合っているか
   - コード進行の役割（トニック → サブドミナント → ドミナント → 解決）、最後が主音で終わるか
   - 歌いやすい音域（男性 A2〜E4、女性 G3〜C5、合成音声 C4〜G5）に収まっているか
   - 言葉のアクセントとメロディの上下、伸ばす音の母音（高音で「い・う」は苦しい）

## 出力形式

YAML は出力しない（この依頼では曲ファイルを書き換えない）。次の構成で書く。

1. **結論**（1〜2 文）: そのまま書き出してよいか
2. **スキーマ / モーラ数 / 理論** の 3 見出し。各見出しに「良い点」「直したい点（場所はセクション名と小節で示す）」「理由（理論の根拠）」
3. **優先度の高い修正 3 つまで**（`revise.md` にそのまま渡せる依頼文の形で）
